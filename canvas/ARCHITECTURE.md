# 画布文档与坐标约定（schema 1）

- `Document` 是业务数据，独立于 Konva：有序图片对象表示层级，图片引用资源 ID；每张图片记录变换、裁剪、标注和区域操作。
- `Asset` 注册表保存不可变原图 URL、原始宽高、名称。运行时使用 blob URL；历史仅复制资源引用，不复制图像。持久化时转换为不可变 PNG 哈希资源 URL。
- 图片局部坐标等于原始像素坐标。图片变换按缩放、旋转、平移顺序应用。标注、裁剪和修改区域都存局部坐标，视口不进入这些数据。
- 裁剪仅改变图片可见区域，原始资源不变。标注与区域超出裁剪边界的部分隐藏。导出以裁剪左上角为原点，输出四舍五入后的裁剪宽高；无裁剪则为原始尺寸。
- 视口独立于文档；平移、缩放、适配、对象选择均不进入历史。一次笔画、一次图片拖动／变换、一次属性修改、一次裁剪各提交一条内容历史。撤销栈上限 80，资源不嵌入历史。
- 原图、标注与区域为独立逻辑层；交互框与裁剪预览仅在交互层。导出直接读取业务文档和全分辨率资源，避免导出 Transformer、选中描边或视口缩放。
- 区域由按顺序重放的画笔、闭合套索、擦除操作组成；内部选区以白色 alpha 表示。PNG mask 适配器输出白色不透明保护区域、透明修改区域，保持 RGBA。后端/渠道接入时需实测此编码。
- 原型入口 `/canvas/`，开发端口 8099；正式入口、生成 API 和任务快照将在 M1/M3 接入。不得把原型中尚未接入的生成按钮视为完成的生成链路。

## M1—M3 接入决定

- 旧 DOM 保留在独立面板；首次切换创建同源 iframe，之后只隐藏，不卸载。顶栏分段控制器每次加载固定选择原界面，不读取持久化的上次选项。图片交换通过验证 origin/source 的 postMessage 协议与明确按钮完成。
- 模型／尺寸／质量目录提取到 `frontend/model-config.json`。FastAPI 注入旧页面；画布独立读取同一文件。动态费用读取现有路由状态接口，不写死金额。
- 每个 `Job` 持有提交时的图片业务快照、设置、来源 IDs、占位位置和任务 ID；请求像素 payload 仅在任务控制器中保存一次，不写入内容历史。结果图片的 `source` 记录 jobId、taskId、parentIds；原图资源不修改。生成状态随项目持久化；刷新后按任务 ID 查询，未确定提交通过 client_request_id 查询，不自动重新提交。
- 准备输入期间禁用重复提交；网络提交未确认时沿用 `client_request_id`，后端按请求指纹去重；已失败任务手动重试创建新 ID。轮询错误不重新生成，404 明确提示服务可能重启。
- 结果占位在提交时定位到文档与已预留任务的右侧；多个任务独立占位。异步回填以最新文档追加新图，保留提交之后的内容操作；回填失败只重试取回已有结果，不重新生成。
- PNG mask 在 API、自动路由和 openai/packy 重试路径中保留；mask 关联第一张主参考图，URL 主图会先获取并固定数据。主图预处理后的最终尺寸同样用于 mask，mask 使用 NEAREST，保留 RGBA。
- 精确保留模式先把上游结果用 LANCZOS 缩放回原图／裁剪图分辨率，再以原始 mask 的反向 alpha 合成。alpha=255 完全保留原图 RGBA；alpha=0 使用生成结果；半透明边缘线性混合。允许传入未标注原图作为保护区域来源，避免烧入指导标记。
- 真实 openai-hk 单次受控验证表明：PNG mask 被接受、中央目标按描述修改，但上游返回的保护区不是像素级不变。精确保留由本服务合成保证，不能向用户声称上游天然精确保留。

- `workspaceStorage.ts` 在 IndexedDB 保存图片 Blob、完整工作区 checkpoint 和最近项目 ID；签名忽略运行时 blob URL，避免恢复时产生伪变更。
- `useWorkspace.ts` 串行执行本地备份与服务器同步，服务器以 base_revision 乐观锁检测多窗口冲突。保存期间发生的新编辑会继续排队保存；退出前本地备份未完成时提示。
- 服务端 `canvas_projects.py` 使用 SQLite 追加版本，图片通过临时文件原子落盘并以 SHA-256 去重。项目、历史版本与图片读取接口位于 `/api/v1/canvas/`。
- `ProjectControls.tsx` 提供命名、保存点、项目列表与版本恢复。恢复旧版使用当前 head 作为下一次保存基线，因此追加分支而不删除旧版本。撤销/重做与时间版本列表分开维护。
